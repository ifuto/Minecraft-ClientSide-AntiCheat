# HeartSMP

Paper 1.21.x 用の SMP プラグインです。
ハート（最大体力）の受け渡し、Combat タグ、カスタムのキルログ／参加退出メッセージ、
TPA、いふと配送（アイテム送信）、RTP、運営用の RollBack ツールをまとめて実装しています。

- 対象: **Paper 1.21.11**（`paper-api 1.21.11-R0.1-SNAPSHOT`）
- Java: **21**
- ビルド成果物: `build/libs/HeartSMP-<version>.jar`

> リポジトリ名 (`Minecraft-ClientSide-AntiCheat`) は仮のもので、中身は上記のプラグインです。

---

## ビルド

### GitHub Actions

`.github/workflows/build-plugin.yml` を利用します。

- 手動実行 (`workflow_dispatch`) でパラメータを指定
- もしくは `trigger.md` を編集して push（`trigger.md` の `key: value` がビルドパラメータになります）

```md
mc: 1.21.11
java: 21
server_test: true
```

`server_test: true` にすると、実際に Paper サーバーを起動してプラグインが Enable されるかまで確認します。

### ローカル

```bash
./gradlew build      # build/libs/HeartSMP-*.jar とテスト実行
```

`gradle.properties` の `minecraft_version` / `paper_api_version` / `plugin_api_version` を書き換えれば、
別の 1.21.x でもビルドできます。

## 実装されている機能

### ハート（最大体力）

- 既定は **10 ハート**（バニラと同じ 20 HP）、上限は **30 ハート**（`settings.hearts`）
- **Combat 中にプレイヤーに倒された場合**
  - 倒された人のハートが **-1**
  - 倒した人のハートが **+1**（上限 30 で打ち止め）
  - 倒した人が特定できない／候補が複数いる場合は、`<#eb4034>Heart` という名前の
    **ネザースター**が所持アイテムと一緒にドロップ（右クリックでハート +1）
- ハート数は属性 `MAX_HEALTH` に直接反映されます（プレイヤーデータに永続化）

### 死亡時のインベントリ

| 死因 | 挙動 |
| --- | --- |
| プレイヤーに殺された | インベントリをその場にドロップ（インベントリ保持なし） |
| Mob / 自然死 | **Keep Inventory**（リスポーン時に死亡時の状態へ復元） |

- PvP のドロップ品には「どの死亡ログで、誰が落としたか」のタグ（PDC）が付与され、
  同時に死亡時インベントリが **gzip + Base64 で超圧縮**して保存されます

### Combat

- プレイヤー由来のダメージを **受けた／与えた双方** を 30 秒間 Combat 状態にします（設定可）
- Combat 中はアクションバーに `<#00D6FF>Combat<#C6C6C6>: <#9BEFFF>%seconds%s`
- **Combat 中にログアウト**すると
  - その場に所持アイテムを半径 4 ブロック程度に散らばせる
  - ハートの推移（相手が 1 人に絞れれば移動、絞れなければ Heart のネザースター）
  - 死亡ログ（`COMBAT_LOGOUT`）として保存され `/inventoryrollback` から復元できます

### キルログ / デスログ

```
<#ff6f4d>⚔️ <bold><name_color_kill>%Killer_Name%</bold> <#ffffff><bold>→</bold> <#00D6FF>💀  <name_color_death>%Death_Name% <#C6C6C6>for <#ffffff>%Item_Name%
```

- `%Item_Name%` はキルに使ったアイテム
  - デフォルト名 → クライアントの言語に合わせたデフォルト名（translatable）
  - カスタム名 → `"名前"` とダブルクォートで囲む
- 透明化中のプレイヤーが殺した場合は `%Killer_Name%` が `§kaaaaaa`（難読化 6 文字）になります
- Mob / 自然死はバニラのデスメッセージのままです

### 参加 / 退出メッセージ

```
<#C6C6C6>[<#7aff59>+<#C6C6C6>] <#ffffff>%JoinPlayer_Name%
<#C6C6C6>[<#eb4034>-<#C6C6C6>] <#ffffff>%LeavePlayer_Name%
```

透明化中のプレイヤーは名前部分が `§kaaaaaa` になります。

### ダメージ調整

- **TNT トロッコ**のダメージを 80% に
- **メイスの防具貫通 (Breach)** を 1 レベルごとに 4% 減（バニラ 15%/Lv → 11%/Lv）
  - バニラの防具軽減式を再計算して、差分をダメージに加算する方式

## コマンド

### プレイヤー向け

| コマンド | 説明 |
| --- | --- |
| `/tpa <player>` | TPA リクエスト送信。期限 50 秒、再送間隔 30 秒。期限内に再送すると**期限を 50 秒延長**して再通知（「期限切れ」メッセージの連発を避けるため）。成功後は 5 分間次のリクエストを送れません |
| `/tpahere <player>` | 受信者を自分へ呼ぶ版 |
| `/tpaccept [player]` | 受信したリクエストを承認（引数なしで最新 1 件）。承認後 **3 秒カウントダウン**、0.3 ブロック以上動くと中止して 15 秒クールダウン（視点移動は OK） |
| `/tpadeny [player]` | 拒否 |
| `/tpacancel [player]` | 自分が送ったリクエストを取り消し |
| `/send <player>` | いふと配送（下記） |
| `/bagages` | 届いた荷物の一覧 |
| `/rtp` | ランダムテレポート（GUI から種類を選択） |

### 運営（`heartsmp.admin`）

| コマンド | 説明 |
| --- | --- |
| `/combat` | Combat 中のプレイヤーを頭付き GUI で一覧。クリックでスペクテイターとして移動し、チャットの `[Back]` で元の場所へ |
| `/inventoryrollback <player>` | その人が「プレイヤーに殺された / Combat 中に抜けて死んだ」ログの一覧（左上ほど最新）。クリックで当時のインベントリ、`RollBack` / `RollBack + EXP` / `Undo` ボタン付き |
| `/rank <player> <default\|VIP\|VIP+>` | ランク変更（RTP の解放条件に使用） |

## いふと配送 (`/send`)

5 行のチェスト GUI。中央がアイテム枠、その上がシュルカー（装飾）、2 マス下がエメラルドブロック（発送）、
3 マス右がダイヤ枠、その上がダイヤ（装飾）、3 マス左が FastSend 枠、その上が羽（装飾）で、
それ以外は水色の板ガラスです。

- 1 回に送れるのは **1 スタック**まで（シュルカーボックス不可）
- 送料は **3 ダイヤ**（FastSend ON なら **6 ダイヤ**）
- 到着は **2 分後**（FastSend ON なら即時）
- 送り主ごとに同時 **3 件**まで
- 以下のアイテムは **「いふと配送 配送規約違反」** として送信できません
  火打ち石 / 火打ち石とうちがね / TNT / デバフ系ポーション / ロケット花火 / クリスタル /
  火薬 / 避雷針 / 不吉な瓶 / シュルカーボックス
- 届いた荷物は `/bagages` に **21 件**までストックでき、
  21 枠埋まっている相手には送信できません

## RTP

`/rtp` で GUI が開き、以下から選べます。安全な足場（2 ブロック分の空間・液体/危険ブロックなし）を
探索してからテレポートします（Mob は考慮しません）。

| 種類 | 内容 | Cooldown | 解放 |
| --- | --- | --- | --- |
| Cave RTP | 地下深くの洞窟へ | 5 分（Biome-Select と共通） | VIP |
| Normal RTP | オーバーワールド地上へ | 40 秒（独立） | ALL |
| Biome-Select RTP | バイオームを選んで地上へ | 3 分（Cave と共通） | VIP+ |

きのこ島（`mushroom_fields`）は選択肢に含まれません。

## RollBack (`/inventoryrollback`)

1. プレイヤー名で検索 → 死亡ログ一覧（左上ほど最新、名前は `<bold>Killer</bold> killed`）
2. ログをクリック → 当時のインベントリ表示 + ボタン
   - **RollBack**: その戦闘で落ちたアイテムを世界中から回収して死亡時の状態に戻します。
     回収対象はオンラインプレイヤーのインベントリ・エンダーチェスト・読み込み済みチャンクの
     チェスト等のコンテナ・地面のドロップ・シュルカーボックスやバンドルの中身まで。
     入りきらない分は地面にドロップします
   - **RollBack + EXP**: 上記に加えて当時の経験値も復元
   - **Undo**: 直前の RollBack を取り消し（元の場所が埋まっていれば地面へドロップ）

回収対象は PDC の死亡ログ ID で判定しています。

## 設定 (`config.yml`)

主な項目（すべて `settings` 以下）:

| キー | 既定値 | 説明 |
| --- | --- | --- |
| `combat.duration-seconds` | 30 | Combat 継続時間 |
| `hearts.default` / `min` / `max` | 10 / 1 / 30 | ハート設定 |
| `death.logout-scatter-radius` | 4.0 | Combat ログアウト時の散らばり半径 |
| `damage.tnt-minecart-multiplier` | 0.8 | TNT トロッコのダメージ倍率 |
| `damage.mace-breach-reduction-per-level` | 0.04 | Breach の貫通を 1 レベルあたり何割減らすか |
| `tpa.*` | - | 期限 / 再送 / クールダウン / カウントダウン / 移動閾値 |
| `delivery.*` | - | 送料 / 到着時間 / 同時件数 / Bagages 上限 / 禁止アイテム |
| `rtp.*` | - | クールダウン / 探索半径 / 洞窟の深さ |
| `rollback.max-records-per-player` | 40 | 1 人あたりの保存する死亡ログ数 |

`messages` 以下にすべての文言（MiniMessage 記法）があります。
`ranks` でランク名とネームカラー（`<name_color_kill>` / `<name_color_death>` に使用）を設定できます。

## 仕様の解釈メモ

実装上の判断をまとめておきます。

- **Heart のネザースター**: 落とした人が分からない場合の「+1 ハート」の器として、
  右クリックでハート +1 になるアイテムとして実装しています
- **キルした人の判定**: `Player#getKiller()` が取れればその人。取れない場合は
  Combat 相手が 1 人だけならその人、0 人または 2 人以上ならネザースターをドロップ
- **インベントリ保持の実装**: 死亡時にスナップショットを取り、リスポーン直後に復元します
  （`keepInventory` ゲームルールに依存しません）
- **TNT トロッコの判定**: 爆発のダメージソース（`DamageSource`）の実体、または近傍の
  TNT トロッコで判定しています。近くで別の爆発が同時に起きた場合は誤判定する可能性があります
- **Breach の軽減**: バニラの防具軽減式で「貫通 15%/Lv」と「11%/Lv」の最終ダメージ比を計算し、
  その比をダメージに掛けることで実現しています（近似）
- **RTP のクールダウン**: メモリ保持（再起動でリセット）。ランクは `players.yml` に永続化
- **RollBack の探索範囲**: オンラインプレイヤーのインベントリ / エンダーチェスト、
  読み込み済みチャンクのコンテナ、地面のドロップ、それらの中のシュルカー・バンドル。
  アンロード済みチャンクのコンテナは対象外です
- **非 PvP のデスメッセージ**: 仕様にキラー名が必要なため、バニラのメッセージを残しています

## 経験値の扱い

- Mob / 自然死・PvP 死のどちらでも **経験値はドロップしません**
- Mob / 自然死はリスポーン時に死亡時の経験値へ復元されます
- PvP 死の経験値は死亡ログに保存され、`/inventoryrollback` の **RollBack + EXP** で復元できます
  （運営が任意で戻すかどうかを決められます）

## 既知の制限

- TPA のリクエストと RTP のクールダウンはメモリ管理のため、サーバー再起動で消えます
- `/inventoryrollback` の回収はチャンク走査を行うため、大規模ワールドでは一瞬重くなる可能性があります
- メイスの Breach 軽減はバニラの計算式を再現した近似です（Protection 等の軽減は乗算で維持されます）
- Keep Inventory は死亡〜リスポーンの間にメモリ上に保持しているため、
  その間にサーバーが強制終了すると復元できない場合があります（通常の退出時は復元します）
